# SMP ResNet34 U-Net: acquisition and preprocessing audit

Audit date: 2026-11-17. **No training, ablation or final preprocessing selection.**

## Acquisition and architecture

Official SMP 0.5.0 source commit [`420ce84b0c2df0286fa9bb2bd1499eea625c9b33`](https://github.com/qubvel-org/segmentation_models.pytorch/tree/420ce84b0c2df0286fa9bb2bd1499eea625c9b33) was downloaded as an archive. The installed package's encoder, channel adaptation, preprocessing, decoder and forward implementation files were byte-identical to that source. No upstream edits were made. SMP code uses the MIT license; checkpoint licensing is listed separately by its model card as `other`, so ImageNet weight usage must retain upstream provenance and applicable terms.

Actual checkpoint: [`smp-hub/resnet34.imagenet/model.safetensors`](https://huggingface.co/smp-hub/resnet34.imagenet/tree/7a57b34f723329ff020b3f8bc41771163c519d0c), revision `7a57b34f723329ff020b3f8bc41771163c519d0c`, 87,275,112 bytes, SHA-256 `6549ccd46a2d20a0a74fca866cfc5c6f9b3672d468b0a92aa94a58545a61103e`. This is an ImageNet encoder checkpoint, **not a pretrained MRI segmentation checkpoint**. Weights stay in the runtime model cache; they are excluded from GitHub.

The requested `Unet(encoder_name='resnet34', encoder_weights='imagenet', in_channels=12, classes=1, activation=None)` initialized and ran on CPU. ResNet34 encoder channels are `[12,64,64,128,256,512]`, at input, /2, /4, /8, /16, /32 scales (ceil behavior for odd dimensions). Decoder blocks output `[256,128,64,32,16]`, interpolate to skip feature sizes and concatenate skips; two convolution/BatchNorm/ReLU layers per block restore resolution. The segmentation head is a 3×3 convolution 16→1, with identity activation: output is logits, not probabilities. Sigmoid and threshold are external decisions.

All supplied encoder tensors other than conv1 remain exactly equal to ImageNet weights. BatchNorm `num_batches_tracked` buffers absent in the old checkpoint are initialized by PyTorch; they are not missing learned weights. Conv1 becomes `[64,12,7,7]`, with **W12[:,c] = Wrgb[:,c % 3] × 0.25**. Exact tensor equality was asserted. This is cycling/scaling, not an RGB semantic match to MRI. The upstream helper's claim that >3 channels are random is a stale docstring: its executed body reuses weights. Decoder convolutions use Kaiming uniform, head uses Xavier uniform, normalization scales/biases start at 1/0; those components have no pretrained segmentation knowledge.

Total parameters: **24,464,593**. Synthetic input `[1,12,H,W]` yielded finite `[1,1,H,W]` for H/W 64/64, 240/240, 256/256, 255/257 and 512/512. In this version U-Net explicitly disables the base class's divisibility check and uses target-size decoder interpolation. Padding to 32 is optional, not mandatory. Extremely small inputs and training-mode BatchNorm with tiny batch/spatial sizes were not validated. Tests use eval/inference mode.

Local CPU peak process RSS was **1,433,042,944 bytes (~1.33 GiB)** over all test sizes, including imports and checkpoint loading, not isolated activation memory or training demand. Exact timing, feature tensors, package versions and platform-specific RSS units are in [local evidence](evidence/local-model.json). The measurement is on macOS CPU and must not be treated as Kaggle/GPU memory sizing.

## Reproduction and dependencies

Internet is needed once for the pinned Hub checkpoint/config; use `HF_HUB_OFFLINE=1` after caching. Set `HF_HOME` to your private runtime cache if required. No R2 credentials are needed for this synthetic test. The script asserts initialization equality and prints a JSON result. It does not train.

Do not install this macOS lock into Kaggle or replace Kaggle's torch with a CPU wheel in a GPU session. A private, no-GPU, no-secret [Kaggle CPU probe](https://www.kaggle.com/code/mathewzhou/novo-smp-resnet34-cpu-audit) completed successfully in its actual current environment. ## Original preprocessing assumptions

Encoder metadata specifies RGB, range [0,1], mean [0.485,0.456,0.406], std [0.229,0.224,0.225]. SMP's standalone HWC preprocessing helper divides by 255 when max>1 and expected range is [0,1], then broadcasts these three-element means/stds. An actual HWC12 call failed broadcasting. Negative MRI values or large positive intensities do not make that heuristic valid. Do **not** apply this helper directly or tile its RGB means/stds across MRI channels. Raw forward accepts floating NCHW tensors and does no intensity normalization, anatomical reorientation, input resizing, input padding/cropping or lesion-aware sampling. Decoder feature interpolation is internal upsampling, not preprocessing of the original input.

## Real UCSD observations

`data_probe.py` used the frozen split and existing immutable all-file audit, then fetched only two train visits through the shared checksum-validating loader. No full-cohort pixel preprocessing ran. No test patient was inspected. [Aggregate evidence](evidence/ucsd-summary.json) contains per-modality nonzero percentiles, mean/std, geometry and memory; raw images and per-patient outputs are not committed.

The positive example is RAS 512×512×184, spacing 0.4883×0.4883×1 mm, 57 enhancing voxels on 4 positive / 180 negative axial slices. The empty-mask example is RAS 512×512×192, spacing 0.5×0.5×1 mm, 0 positive / 192 negative slices. These are representative observations, not proof of uniform cohort orientation or spacing. Nonzero maxima across modalities reach 8,729 versus very different medians; shared RGB normalization is inappropriate. Four full float32 input volumes alone consume 771,751,936 / 805,306,368 bytes; raw masks, arrays, resampling and temporary copies add memory. One 12×512×512 float32 stack is 12 MiB. Cache volumes once per visit or use bounded slice caches; do not download/decompress four complete gzip files for every stack.

Existing audit histograms cover **746 train visits and 215,680 native axis-2 slices**; 48 completely empty raw masks, 66 visits with no label 3, and 51 positive visits with fewer than 100 enhancing voxels. Enhancing voxel counts per visit at percentiles 0/25/50/75/90/99/100 are 0/352.5/2222/12298/44876/185995/480979. Small positive *visit volumes* do not measure individual-lesion prevalence: connected-component statistics would be needed for that claim. The exact train positive/negative **slice** totals are not derivable from the prior per-volume histograms and remain unmeasured. We deliberately did not launch a full-cohort mask pass under this task's restriction. Total native axis-2 slices must not be confused with canonical axial slices if orientations differ.

The complete prior audit reported no modality-grid failures. The shared loader aligns all modalities to native T1c, but that alone does not ensure a consistent anatomical slice axis across visits. Two masks with unknown units retain the existing explicit aligned-mm policy. Preserve raw labels and files.

## Preprocessing alternatives for review — proposals only

| Decision | Mandatory compatibility | Options and proposed initial default | Small-lesion / longitudinal consequence |
|---|---|---|---|
| Geometry and slice axis | Resolve valid mm geometry; align modalities and masks to the same T1c; use physical orientation consistently | Reorient aligned data to RAS by lossless axis permutation/flips, use canonical axial axis 2. Oblique scans may require an explicit common physical grid, reviewed separately | Native axis 2 alone can mix anatomical directions. Reorientation must retain an invertible map to the original T1c |
| In-plane size | Identical image/target transforms and exact restoration | Prefer native resolution initially; optional symmetric padding with recorded margins. Resizing to 256 or 240 saves compute but is not required by SMP | Downsampling can remove lesions as small as the 57-voxel example. Full-resolution tiles need coverage/overlap controls |
| Intensity | Replace incompatible RGB helper; per-modality finite float32 data; no label-driven masks | Propose per-volume, per-modality nonzero z-score; keep zeros zero, guard empty/constant channels. Optional 0.5–99.5 percentile clipping then z-score | MRI nonzero voxels are a foreground proxy, not a verified brain mask; review skull/noise. Clipping can suppress genuine enhancing extremes. Compute stats once per volume, not per slice |
| Context | Freeze and record 12-channel order and center target | Proposal: modality-major `[T1(z−1,z,z+1), T1c(...), T2(...), FLAIR(...)]`; replicate boundary slices. All three planes share the volume normalization | Index-adjacent spacing varies across visits; physical offsets (e.g. ±2 mm) offer comparable context but require documented sampling/interpolation. Do not silently mix approaches |
| RGB adaptation | Record the exact default 12-channel weight map | Start with unmodified SMP cycle×0.25; optional channel-mean replication or learned projection are future modeling choices | Modality-major ordering creates arbitrary RGB-to-MRI associations; changing order/adaptation needs an explicit new experiment config |
| Sampling | Keep frozen patient partitions, evaluation complete and unweighted | Candidate 50% positive-center / 50% negative-center sampling, with patient/visit balancing and negatives from both tumor-bearing and empty visits; ratio is undecided | Oversampling can improve tiny-lesion exposure but skew FP calibration. Avoid unbounded repetition of a few tiny cases; never oversample validation/test |
| Restoration | Export complete native T1c shape/affine with shared prediction contract | Save reorientation/grid/crop/pad/resize metadata; undo padding/crop, resize logits if used, invert axis transforms, sample into original T1c, then sigmoid/threshold; preserve nearest-neighbor semantics for discrete masks | Logits interpolation and threshold order matter; never resample truth linearly. Report original-space shared Dice/HD95 and visit-local lesion candidates, not cross-time identities |

Native resolution, nonzero z-score, adjacent voxel context and default weight adaptation are **proposals, not selected final settings**. Brain masks, clipping percentiles, physical context and sampling ratios need owner review before training implementation. No preprocessing ablation was launched.

## Next-step handoff / acceptance limits

Acquired weights, pinned source, exact 12-channel adaptation, CPU inference and two real train visits are verified. Preserve Protocol v1 split/input modality names, primary target raw label 3, shared evaluator and original T1c prediction contract. Do not infer lesion identities from tissue labels or connect components across visits without the tracking method.

Before GPU fine-tuning: approve orientation/oblique-grid policy, native versus resized/tiles, foreground/statistics rule, context/channel order/boundaries and initial sampling. Decide whether to authorize an exact all-training-mask slice/component census; current per-volume data does not supply those counts. Confirm the target GPU/framework environment independently and choose losses/threshold calibration using training/validation only. No training code or final preprocessing configuration is introduced here. Stop after this audit; GPU fine-tuning requires a separate decision.
