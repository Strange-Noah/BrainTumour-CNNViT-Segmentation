# Formal training execution and recovery

The current authoritative protocol is [adaptive two-phase training](ADAPTIVE_TRAINING.md), superseding the former 30-pass proposal. [Focused correctness evidence](ADAPTIVE_ACCEPTANCE.json). The owner has authorized this task to use currently available free GPU allowance; no paid resources or automatic future quota renewal. Configuration keeps authorization false/zero by default; actual owner-controlled dispatch supplies `formal_training_authorized=true`, `free_resource_authorized=true`, mode=formal, and the existing frozen private full-cohort input. Never forge GITHUB_ACTOR or run unintegrated source with credentials.

The existing manual Actions bridge pins integrated main source and exact private input version, reuses accepted CPU data-read evidence, refreshes GET-only expiring leases and restores the current science-compatible checkpoint. No imaging re-preparation or republication. Dual T4 FP32 uses the existing ≤12h provider timeout, a ten-minute finalization margin and quota-derived cumulative safety guard.

Normal execution emits aggregate training events every 100 updates (and first update), including phase, unique coverage, global samples/s and optimizer steps/s, loading wait, finite status, available RAM and GPU memory/utilization. Atomic valid checkpoints every ten minutes emit a checkpoint_saved event; no identifiers, tensors or URLs appear in telemetry.

After approximately ten minutes of actual updates, the initial Actions job records measured health, current quota, checkpoint evidence and execution URL, then exits active observation. Kaggle continues independently. The existing half-hourly collector transfers outputs to private R2, independently SHA-verifies them, updates the resume pointer and retains separate best checkpoints. No active campaign means no-op. Actual correctness failures are recovered without automatic GPU retry; ambiguous submission is never resubmitted blindly.

Successful provider boundaries resume the same phase, frozen draw plan and consumed cursor only while the recorded allowance and current quota permit. Quota exhaustion or renewal reports PAUSED_RESOURCE_LIMIT, not convergence. Only complete-cohort validation may produce TARGET_REACHED or PLATEAU_BELOW_TARGET. Existing cron/manual recovery is the sole continuation mechanism; no new scheduler or manual notebook cells.
