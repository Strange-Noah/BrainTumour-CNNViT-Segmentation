In GitHub environment `tcia-ingestion`, store the writer as `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`. Store the read-only pair under the same names in `tcia-verification`. Both environment endpoints, main-only rules, and reviewer protections are already in place. GitHub now lists both secret names in each environment. Apply the branch and environment rules in the [promotion plan](promotion.md#cutover). Keep the key values in the secret store. An optional `TCIA_FASPEX_URL` secret can supply the official package link if discovery fails. [GitHub environments](https://github.com/Strange-Noah/BrainTumour-CNNViT-Segmentation/settings/environments)
2. **Kaggle outputs.** Create the permanent private `novo-nordisk-pbl-outputs` bucket. Add the output-bucket-only read/write pair as `R2_OUTPUT_ACCESS_KEY_ID` and `R2_OUTPUT_SECRET_ACCESS_KEY` in the private Kaggle smoke notebook. Configure an output-bucket read-only pair for the recovery notebook or session. Keep the existing dataset keys read-only. Set `R2_OUTPUT_BUCKET=novo-nordisk-pbl-outputs` in the smoke run. If saved versions keep failing at Kaggle Secrets, a single interactive run and a fresh interactive recovery session are the verified fallback. [Private Kaggle verification notebook](https://www.kaggle.com/code/mathewzhou/novo-tcia-and-r2-verification)

The jobs accept no pull-request code and publish only aggregate results.
